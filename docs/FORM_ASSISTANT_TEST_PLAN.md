# Zing Zone Form Assistant — Test Plan and Verified Scope

## Implemented in source code (not yet certified on a real phone)

- **OCR:** on-device ML Kit text recognition for Latin and Devanagari scripts; user can select up to five images, crop each, and review extracted text before sending it to AI. This is image OCR, not multi-page PDF OCR.
- **Field discovery:** the in-app WebView reads visible page text and ordinary input/select/textarea metadata, including labels, IDs, names, autocomplete, constraints and select options.
- **AI field suggestions:** the prompt explicitly separates applicant, father, mother and guardian names; DOB and issue date; permanent and correspondence address; qualification and marks; photo, signature and thumb impression. Unknown or ambiguous suggestions should be omitted. Suggestions are shown for user review.
- **Draft-fill safeguards:** password, hidden, file, submit, button, reset, checkbox, radio and image controls are excluded from ordinary autofill. Basic select-option, length, pattern, date, email and numeric checks run before filling. The form is not submitted.
- **Evidence gate:** Worker has a deterministic gate that only accepts confirmed user facts, high-confidence OCR facts confirmed by the user, or verified profile evidence. AI inference alone is rejected. Manual fill values are explicitly user-confirmed after the review UI.
- **Eligibility:** preliminary comparison against the currently visible page/notice text and user-confirmed facts. It is not an official eligibility decision or a live rules database.
- **Photo background removal:** on-device selfie/person segmentation produces a transparent PNG draft and preview. It is intended for a single-person portrait; it does not guarantee passport-photo compliance and does not itself upload the image to a portal.
- **Android overlay:** native floating bubble/panel service and an opt-in Accessibility page reader are generated by the build workflow. The user must grant Android overlay permission and separately enable the accessibility service. The current reader is limited to supported browser accessibility trees and approved government domains; it displays page analysis in the floating panel. It is not universal cross-app form automation.
- **Portal adapter registry:** workflow guidance exists for SSC, UPSC, RPSC, Rajasthan SSO, UIDAI, EPFO, PM-KISAN, National Scholarship Portal, Parivahan/Sarathi/Vahan, Income Tax e-Filing, GST, e-Shram, National Career Service, Passport Seva, DigiLocker, Election Commission voter services, Rajasthan Staff Selection Board, Rajasthan Jan Aadhaar, MGNREGA, NFSA and ServicePlus/e-District. Adapters are guidance metadata, not portal-specific automation scripts.

## Known gaps — do not describe these as completed

- Cross-document identity ownership is not yet a deterministic verified feature. OCR text is separated by image, but the app still needs a structured document profile (document type, person/owner, field, source quote, confidence) and explicit user confirmation before treating extracted facts as reusable profile facts.
- Multi-page PDF OCR, PDF page splitting, image quality scoring, blur/glare detection and automatic document classification are not implemented.
- Recruitment eligibility does not yet fetch and verify the exact current notification, corrigenda, cut-off date, age-relaxation tables and post-specific rules from official sources. The current comparison only uses page text already visible in the app.
- Background removal is limited to person segmentation. Government-specific photo dimensions, file-size presets, background-color replacement, signature/thumb cleanup and portal upload adapters are not complete.
- The floating panel is not a full universal overlay form assistant. It does not inject values into arbitrary third-party apps. Accessibility page reading may fail in browsers that hide their accessibility tree, and it does not support every browser, iframe, custom control or portal.
- Portal registry entries provide service-specific guardrails only. There are no tested selectors/state machines for every portal, every page version, every state e-District implementation or every application journey.
- Real Android device testing, Vivo device testing, actual browser testing and official portal end-to-end testing are still required.
- Worker-side rate limiting is best-effort unless a Cloudflare rate-limiting binding is configured. Production monitoring, privacy retention controls and consent audit trail need review.

## Mandatory safe test sequence before using real information

1. Use only fake sample documents and the built-in demo form.
2. Confirm OCR text against the source image; intentionally test similar names and different document owners.
3. Verify applicant, father, mother and guardian values remain distinct. If owner or field meaning is unclear, the value must stay blank.
4. Test valid and invalid select options, max/min length, pattern, date, email and numeric limits.
5. Confirm password, OTP, CAPTCHA, file, payment, bank/card, checkbox/radio and submit controls are never autofilled.
6. Test photo segmentation on a sample portrait and inspect hair/ear/shoulder edges against a checkerboard/contrasting background; do not assume the output is accepted by a portal.
7. Grant overlay permission only after reading Android's permission screen; enable Accessibility only after reviewing the consent notice. Confirm the reader ignores login, profile, dashboard, OTP, CAPTCHA and payment pages.
8. Test each portal adapter on public information pages only. Do not test with live personal data until privacy, consent and data handling have been reviewed.
9. User must personally review every field and handle OTP, CAPTCHA, biometrics, fees/payments, declarations and final submission.

## Safety and correctness

No AI form system can promise zero errors or guaranteed eligibility. If a source, document owner, field label, value, portal rule or photo requirement is uncertain, stop and ask the user. A successful APK build proves compilation only; it does not prove that the feature works on a real phone or completes a real government application.
