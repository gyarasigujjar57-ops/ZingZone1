## Implemented in source — not yet phone-certified
- Firebase Authentication Google and phone OTP flows.
- Chat requests routed to Cloudflare Worker by default.
- Live Form in-app WebView for HTTPS pages, visible page text, and ordinary form controls.
- Up to five image documents can be selected, cropped and OCR-read on-device in Latin and Devanagari. Text is kept separated by image source and shown for user review.
- AI field suggestions distinguish applicant/father/mother/guardian, DOB/issue date, permanent/correspondence address, qualification/marks and photo/signature/thumb impression. Values without direct source evidence are rejected.
- A second deterministic Worker confidence gate checks source confirmation, field label presence, basic format and select-option match before draft autofill.
- Autofill is limited to ordinary text/select/textarea fields. Password, hidden, file, submit, button, reset, checkbox, radio and image controls are excluded. No final submission is automated.
- Preliminary eligibility comparison uses only the visible page/notice text and user-confirmed facts; it does not fetch a complete official rule database.
- On-device selfie segmentation produces a transparent PNG preview draft. It does not certify official photo compliance or upload the result to a portal.
- Native Android floating bubble/panel and opt-in Accessibility page-reader services are generated by the APK workflow. User permission is required. They have not yet been verified on a physical device.
- Worker portal adapter registry contains service-specific guidance for major central and Rajasthan portals. These are safety/workflow metadata, not tested selectors or full site-specific automation scripts.

## Remaining work / known limitations
- Deterministic cross-document owner reconciliation is not complete. The OCR output is source-separated, but a structured document profile (document type, person/owner, field, source quote, confidence) and explicit confirmation per extracted fact are still needed.
- Multi-page PDF OCR, automatic document classification, blur/glare checks and OCR correction tooling are not implemented.
- Eligibility needs an official-notice retrieval/versioning pipeline, corrigenda handling, cut-off date and post-specific rule engine with citations.
- Background removal needs manual edge review, background-color replacement, portal photo-size presets, signature/thumb processing and safe upload integration.
- The overlay is not universal cross-app form automation. Accessibility trees may omit content; arbitrary third-party app injection, every browser, iframes, shadow DOM, custom controls and anti-bot pages are not supported.
- Portal adapters still need per-site selectors/state machines, test fixtures, version monitoring and end-to-end tests. Registry metadata alone is not an adapter that can fill every form.
- Worker rate limiting is best-effort unless a Cloudflare rate-limiting binding is configured. Production monitoring, privacy retention controls and consent audit trail need review.
- Store, Rewards, Wallet and Premium are not verified live financial services.
- No physical-device or live government-portal test has been completed in this work session.

## Safety and privacy requirements
- Never ask users to enter OTP, passwords, CAPTCHA answers, full bank/card credentials or biometric secrets into AI prompts.
- The user must personally handle OTP, CAPTCHA, consent, payments, declarations and final submission.
- Obtain clear consent before sending document/page content to Gemini. Minimize retention of identity data and review privacy controls before public release.
- Check each portal's terms and compatibility individually.
- If the source, document owner, field label, value or rule is uncertain, stop and ask the user rather than guessing.
